## 2. Cloudflare 资源创建（一次性）

### 2.1 D1 数据库

```bash
npm install -g wrangler
wrangler login

wrangler d1 create ai-text-tools-db
# 记下输出的 database_id，填入 wrangler.toml

# 应用迁移（本地 + 远程）
wrangler d1 execute ai-text-tools-db --local  --file migrations/0001_init.sql
wrangler d1 execute ai-text-tools-db --remote --file migrations/0001_init.sql
```

### 2.2 KV 命名空间

```bash
wrangler kv namespace create RATE_LIMIT
wrangler kv namespace create CACHE
# 记下两个 id，填入 wrangler.toml
```

### 2.3 Turnstile

Cloudflare 控制台 → Turnstile → Add site（选 Managed 模式，域名填生产域名 + `*.pages.dev`）→ 得到 `siteKey`（前端用）与 `secretKey`（服务端用）。

### 2.4 wrangler.toml 最终形态

```toml
name = "ai-text-tools"
compatibility_date = "2026-09-01"
pages_build_output_dir = "./dist"

[[d1_databases]]
binding = "DB"
database_name = "ai-text-tools-db"
database_id = "<step-2.1 输出>"

[[kv_namespaces]]
binding = "RATE_LIMIT"
id = "<step-2.2 输出>"

[[kv_namespaces]]
binding = "CACHE"
id = "<step-2.2 输出>"
```

## 3. 代码部署（Cloudflare Pages）

### 3.1 连接 Git（推荐，自动 CI/CD）

1. 仓库推到 GitHub
2. Cloudflare 控制台 → Workers & Pages → Create → Pages → Connect to Git → 选仓库
3. 构建设置：
   - Framework preset: **Astro**
   - Build command: `npm run build`
   - Build output: `dist`
4. 环境变量（Settings → Environment variables，Production 与 Preview 都加）：

   | 变量 | 来源 |
   |---|---|
   | `DETECT_PROVIDER` / `DETECT_API_KEY` | 检测供应商控制台 |
   | `DEEPSEEK_API_KEY` | DeepSeek 控制台 |
   | `PAY_PROVIDER`（`morr` 或 `stripe`）及对应密钥/产品 ID（MoR 用 FastSpring/Creem，Stripe 为 LLC 升级后路径） | 支付，见 §5 | §5 步骤产出 |
   | `RESEND_API_KEY` | Resend 控制台 |
   | `TURNSTILE_SECRET_KEY` | §2.3 |
   | `AUTH_SALT` | `openssl rand -hex 32` 生成 |

   > 秘密类变量勾选 **Encrypt**。改完必须 **Retry deployment** 才生效。

5. 之后每次 `git push` 自动部署 `main` → Production，PR → Preview（临时预览域名，方便验证）

### 3.2 本地开发

```bash
npm install
cp .dev.vars.example .dev.vars   # 填入本地秘钥（git 已忽略）
npm run dev                       # http://localhost:4321
wrangler d1 execute ai-text-tools-db --local --file migrations/xxx.sql  # 新迁移先本地
```

> 本地的 D1/KV 是模拟环境（miniflare），数据在 `.wrangler/state`，删掉即重置。

### 3.3 数据库迁移纪律

- 迁移文件按序号命名：`0002_add_xxx.sql`、`0003_...`
- **只用加列/加表/加索引，禁止 DROP/改列**（D1 不支持事务性改表，先加新列迁数据再停用旧列）
- 远程执行前先备份：`wrangler d1 export ai-text-tools-db --remote --output backup.sql`

## 4. 域名与 DNS

1. Cloudflare Registrar 注册域名（或从别家转入）
2. Pages 项目 → Custom domains → Add → 填裸域 + `www`
3. 按提示添加 CNAME 记录（Pages 通常自动接管 DNS）
4. 等证书签发（~5 分钟），HTTPS 强制开启（SSL/TLS → Full (strict)）

**缓存规则**（Speed → Caching，一次性配置）：
- `/r/*` 分享页：Cache Everything，Edge TTL 1 天
- `/_astro/*` 构建产物（带 hash）：Cache Everything，Edge TTL 1 年
- `/api/*`：Bypass cache

**安全响应头**（Pages 项目根目录 `_headers` 文件，构建时自动带上）：

```
/*
  X-Frame-Options: DENY
  X-Content-Type-Options: nosniff
  Referrer-Policy: strict-origin-when-cross-origin
  Content-Security-Policy: default-src 'self'; script-src 'self' https://pagead2.googlesyndication.com https://js.stripe.com; frame-src https://challenges.cloudflare.com https://js.stripe.com; connect-src 'self' https://api.stripe.com;
```

## 5. 收款配置（中国大陆开发者：MoR 优先，Stripe 为升级路径）

> **重要**：Stripe 不支持中国大陆个人注册。零预算阶段用 MoR（Merchant of Record，
> 商户记录人）收款——平台是法律上的卖方，替你处理全球税务，个人身份即可签约。
> MoR 的结账页/订阅/webhook 集成模式与 Stripe 几乎一致，代码层可平滑切换。

### 5.1 阶段一：MoR（上线即用，$0 成本，费率约 5% + $0.50）

| 平台 | 中国大陆个人 | 说明 |
|---|---|---|
| **FastSpring** | ✅ | 老牌 MoR，Individual 账户可签约；Payouts 门户支持汇入中国银行账户 |
| **Creem / Dodo** | ✅ | 新一代 MoR，明确支持中国卖家，电汇提现 |
| ~~Paddle~~ | ❌ | 卖方所在地不支持中国大陆，审核会被拒 |

操作要点：
1. 注册 MoR 账户（个人身份，邮箱 + 身份材料）
2. 建两个订阅产品：$4.99/月、$39/年（对应替换环境变量 `PAY_*` 为 MoR 的产品/链接 ID）
3. 订阅管理链接用 MoR 自带的客户门户
4. 提现：MoR → 万里汇 WorldFirst（结汇 0.3% 封顶）或 Wise → 人民币入国内卡
5. 注意个人年度 $50,000 结汇额度；经营所得依法申报纳税，保留流水记录

### 5.2 阶段二：美国 LLC + Stripe（MRR > $1000-2000 时升级，费率 2.9%）

1. 注册怀俄明州 LLC（~$200-300/年，含注册代理）→ 申请 EIN（免费）
2. 开 Mercury 或 Wise Business 对公账户（免费，接受非美居民 LLC）
3. 以美国实体注册 Stripe，替换 MoR 结账
4. 年度义务：向 IRS 报 5472 表（DIY 或 ~$100-300 会计师）

### 5.3 Stripe 配置（升级到阶段二后执行）

1. **产品与价格**（测试模式先建一遍，上线时切 live 重建）：
   - Product: `Pro`；Price A: $4.99/month recurring；Price B: $39/year recurring
   - 记两个 price_id → 环境变量
2. **Customer Portal** 开启（Settings → Billing → Customer portal）：允许取消、换套餐、更新卡
3. **Webhook**：Developers → Webhooks → Add endpoint
   - URL: `https://<域名>/api/stripe/webhook`
   - 事件：`checkout.session.completed`、`customer.subscription.updated`、`customer.subscription.deleted`
   - 拿到 signing secret → `STRIPE_WEBHOOK_SECRET`
   - 本地调试用 `stripe listen --forward-to localhost:4321/api/stripe/webhook`
4. **自测清单**（live 前必须全绿）：
   - [ ] 测试卡 `4242...` 走完 Checkout → users.plan 变 pro → 额度解锁
   - [ ] Portal 取消订阅 → webhook 同步 canceled → 额度回落
   - [ ] 测试卡 `4000000000000341`（扣款失败）→ 状态 past_due 不炸

## 9. 常见故障排查

| 症状 | 排查顺序 |
|---|---|
| 部署后 API 401/500 | Pages 环境变量是否漏加/未 Retry deployment |
| Webhook 收到但用户未升级 | `wrangler d1 execute ... --command "SELECT * FROM subscriptions"` 看是否落库；验签 secret 是否 live 版本 |
| Turnstile 一直转圈 | sitekey 域名是否包含当前访问域名（含 pages.dev 预览域）|
| 匿名额度"永远用不完" | KV 绑定是否指向生产命名空间（Preview/Prod 用同一 KV）；TTL 是否写成秒 |
| 分享页 404 | `/r/[id]` 是否被缓存规则 Bypass；D1 是否 remote 迁移过（常见坑：只跑了 --local）|
| 检测全部 DETECTOR_BUSY | 供应商余额/状态页；抽象层降级逻辑是否误伤（不计额度的确认）|

## 10. 回滚

- Cloudflare Pages → Deployments → 历史部署 → **Rollback to this deployment**（秒级回滚静态层）
- 数据库不随部署回滚——迁移前备份（§3.3），坏迁移用 `000N_revert_xxx.sql` 反向修
- Git 层：`git revert` + push，走正常部署流水线
